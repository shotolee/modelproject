# 协作提示词

默认由一个主负责人（通常 Codex）保持连续上下文，独立 reviewer 使用未参加实施的另一会话；不要求每轮切换模型品牌。按规则自动形成本地 Git 检查点，远程推送、合并和部署另需授权。

## 开始：只整理大需求

```text
我的项目和想法：<自然语言描述，可分批补充>。
请整理 docs/requirements/product.md，只追问影响当前工作的业务问题。
不要让我拆子需求或写技术规格。当前只整理需求，不设计、不编码。
检查 Git、进入任务分支，检查文档并提交本轮需求记录。
```

## 主负责人：设计与计划

```text
本轮目标：<说明功能和范围>。
你是持续维护本任务上下文的主负责人，先设计和规划，不编码。
读取 AGENTS.md、产品需求、近期变更、相关代码与设计，不必重新阅读全部历史。
细化功能、模块、数据、接口、步骤、允许文件、必须保持行为和验收方法，
更新 architecture.md、implementation-plan.md 和必要的 decisions.md。
在计划顶部维护简短当前摘要，区分有效要求、未决问题和已失败方案。
已有旧记录先保留 Git 历史，不能累积所有 FIX 全文或沿用旧通过结论。
Ready 后提交设计，交接真实分支和设计 SHA 作为固定评审起点，然后停止。
```

## 主负责人：继续实施（默认原会话）

```text
按当前 Ready 计划继续实施，你可以直接编码。
先核对任务摘要、相关设计、代码和 Git 状态，简述目标、范围、必须保持行为和下一步。
发现矛盾先处理，已有明确授权不重复向我确认。
按可验证的小步骤实施、运行相关检查并提交，更新当前状态和实际证据。
不要改业务意图、验收或公开契约，不用测试数量代替覆盖证据。
交付前提交全部本任务变化，提供固定起点、实施 SHA、结果与遗留问题。
转交独立评审后停止修改任务输入，不自审，不自动创建其他会话。
```

## 按需交给 MiniMax / Kimi / 其他协作者实施

```text
你是本轮指定实施者，任务：<一个边界明确的小增量>。
主负责人：<会话或负责人>；固定起点：<SHA>。
读取计划当前摘要和相关设计，核对真实 Git 状态，简述理解后实施。
允许文件、不可修改契约、验收和验证以当前计划为准，不自行重设计。
进展检查时间：<本任务约定的时间>；届时须提供实际改动、验证或阻塞证据。
每步检查、验证、提交，只在计划分配的记录区追加证据，不改主负责人摘要。
共享工作区本轮仅你写入，不另起任务；交付后读回记录、核对版本和状态并停止。
报告实际结果，不能自审或标 Done；额度或执行失败如实保存，不反复重试同一失败。
```

主负责人先确认旧执行完成或停止、实际文件及最后提交再转交。复用原实施会话处理普通修复；模型不适配或额度失败时按事实调整，不固定等待某个品牌恢复。协作者不是必须步骤。

## 独立 reviewer：检查固定交付

```text
你没有参加本任务实施，独立评审固定版本。
起点：<设计SHA>；实施交付：<实施SHA>；本轮功能：<名称>。
先核对检出和工作区，只修改 docs/review-report.md。
评审任务完整 diff、相关产品/验收/设计与受影响调用链，不能只信完成声明。
分类实现缺陷、必需证据缺口及可选改进，给出等级、具体证据、验收依据和最小修复建议。
新偏好不能变成强制验收；新实证安全/正确性缺陷如实阻塞并交主负责人裁决。
记录实际检查；复用证据注明来源版本和适用理由，不重复无必要的重型检查。
写完读回，核对唯一当前结论及被评审 SHA，仅提交报告，
再读取该报告提交确认内容；交接报告 SHA、实施 SHA 和阻塞项，然后停止。
输入变化或交付不一致保持 Pending，不修代码、不猜测覆盖来源。
```

主负责人在 reviewer 活动期间停止编辑任务文件。收到交付后读取确切报告提交，不用聊天摘要或可变文件替代。

## 普通修复与两轮收敛裁决

```text
针对当前报告问题 <R编号>，按已裁决范围修复，保留原起点和已关闭问题。
沿用原实施会话，修改后验证并提交，将新实施 SHA 交独立 reviewer 复核。
只复核该问题及受影响回归，范围或契约变化时扩大审查；不降低验收。
在计划按问题编号累计交付修复次数，换模型或会话不清零。
同一阻塞项两轮仍未关闭时停止自动派发，由主负责人复现、核对验收并作收敛裁决，
明确小范围修复、调整实施者或设计修订后再继续。可选建议不自动变成下一轮任务。
```

## 主负责人：最终验收

```text
读取确定的报告提交和对应实施版本，核对独立性、阻塞关闭证据、测试、产品意图和架构。
只对疑点做必要检查，不机械重做全评审，复用证据明确注明适用版本。
在 audit-report.md 写结论，记录报告 SHA、实施 SHA、延期项理由和未验证限制。
交付矛盾先保持 Pending 并协调，不能猜测报告来源或把旧 PASS 套用到新代码。
本轮独立评审和验证完成、无阻塞且改动全部提交时设 Done，提交最终记录。
不要把局部验收当成产品完成，不自动推送、合并或部署。
```

## 新增或修改需求

```text
新增 / 变化：<目标与原因>。
主负责人同步 product.md 和简短 change-log.md，分析影响并更新架构、计划与必要决策。
保持当前摘要清晰，保留历史 Git 记录；正在执行时先协调写入权，不并行改同一工作区。
先设计不编码，除非我另有实施授权。具体功能拆分由你完成，不让我新增需求编号体系。
```

完整自动推进或委派必须由用户明确授权，不能仅因本模板包含这些提示词就自动启动。主负责人可以继续自身已授权工作；独立评审始终由另一会话完成。
