# 当前实施计划

由 Codex 细化任务和验收，实施 Agent 记录执行结果。用户无需先编写详细需求规格。

## 本轮任务

- 目标 / 对应产品功能或章节：待填写
- 状态：待规划
- 本轮做什么：待填写
- 本轮不做什么 / 不允许修改的范围：待填写
- 任务分支 / 任务开始 commit：待填写
- Git 评审起点：待填写（设计提交 SHA，由实施者在编码前登记，本轮保持不变）

状态可用：待规划、Ready、实施中、待评审、待终审、Done、受阻。本轮范围明确、设计和验证方案就绪后才设 Ready。

## 实施步骤与验收

Codex 从产品意图推导具体步骤和可观察的完成标准；需要新增业务规则时先澄清，不要求用户预写验收编号。

| 步骤 / 对应功能 | 涉及文件 | 完成标准 | 测试命令或验证方法 | 进度 |
| --- | --- | --- | --- | --- |
| 待填写 | 待填写 | 待填写 | 待填写 | 未开始 |

检查正常流程、适用的边界和错误情况，以及原有功能回归。验证方法根据真实项目确定。
每个有意义的实施步骤验证后提交；步骤过大时由 Codex 在规划阶段划分可验证的提交单元。提交不是只在全部编码结束时执行。

| --- | --- | --- | --- |
| 设计提交 / 评审起点 | 待实施者登记 | 待填写 | — |

每次检查点在日志或下一次记录更新时登记实际 SHA，无需反复 amend 提交以填写自身哈希。评审与审计报告引用被检查的实施 commit；报告自己的提交 SHA 在交接消息或 Git 日志中提供即可。

## 实施记录

- 修改文件及行为：尚未实施
- 实际测试命令 / 操作与结果：未运行
- 未验证项及原因：待填写
- 遗留问题或需求 / 架构冲突：待检查
- 下一步：完成设计与计划
- 交接分支 / 最新检查点 commit：待填写
- 本任务未提交文件：待检查（交接前应无）
- 无关用户改动：待检查（保留并说明）
- 远程备份情况：待填写（未授权不推送）

实施者不得自行改既定范围、验收或架构。发现冲突或中途需求变化，暂停受影响部分并交回 Codex 调整。Done 只表示本轮已通过验证与终审，不表示整个产品完成。
