# 产品需求

用自己的话描述即可，也可以直接告诉 Codex，由它整理和维护本文件。这里只写希望产品具备什么能力，具体设计与验收由 Codex 完成。以下是空白模板，不代表已有真实项目需求。

## 1. 项目说明

待填写：想做什么项目，要解决什么问题。

## 2. 使用对象

待填写：谁会使用，在什么场景下使用。

## 3. 核心目标

- 待填写：最希望解决的问题或获得的结果。

## 4. 功能需求

### 功能名称（填写时替换）

用几句话描述希望具备的能力和结果即可。不必写数据库、接口、页面组件或技术方案；按需增加同级小节。

## 5. 使用约束

待填写：使用环境、数据存放、设备支持、时间或预算等已知限制；没有明确限制可写“暂无”。

## 6. 当前不做

待填写：本期不需要的能力。未来想法可放这里并明确标记，确定要做时再移入功能需求。

## 待确认问题（按需）

由 Codex 列出影响当前设计的关键问题；有明确答案后更新对应正文。无问题时可删除本节。
